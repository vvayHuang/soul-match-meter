## 1. 一句話說明

一台假裝很專業的「紅外線熱像儀」：兩個還不熟的人各自回答 3 題白痴問題、按住 5 秒測量，交換序號後拿到一份毫無根據、但很好聊的「配對報告」。

## 2. 為什麼要做

- 剛認識（交友軟體、朋友介紹、網友）時很難開話題，「骰話題」類工具太無聊。
- 大多數雙人小遊戲要面對面或要帳號，門檻太高。
- 想做一個像《賽博燒金紙》那種「很廢但有記憶點」的小 App，同時當作學 SwiftUI 的第一個作品。

## 3. 目標與非目標

**目標**
- 單人流程 1 分鐘內玩完。
- 兩人非同步、遠端就能完成，不需要帳號、不需要後端。
- **兩人看到同一個結果**，結果好笑、值得截圖。
- 風格一致：一本正經的儀器介面 + 很廢的內容（反差就是笑點）。

**非目標（v1 不做）**
- 真的心理測驗或準確配對；真的測體溫。
- 聊天、好友系統、帳號登入、雲端同步。
- 過重的在地梗。

## 4. 目標使用者

| 使用者 | 情境 |
|---|---|
| 交友軟體剛配對的兩人 | 聊了幾句不知道接什麼 |
| 曖昧中、遠距離的人 | 想要一個輕鬆互動的藉口 |
| 朋友之間 | 純粹好玩，測完互相嘴 |

## 5. 視覺與體驗概念

- **熱像儀 HUD**：黑底、準星、溫度讀數、色階條、掃描線、等寬字體。
- **模擬熱像鏡頭**：前鏡頭畫面經 Vision 辨識人臉/身體，模擬成熱像（臉最熱、背景冷），加低解析、雜訊、NUC 快門等「真儀器感」。只在手機上即時處理，不儲存不上傳。
- **陀螺儀視差**：手機傾斜時 HUD 會微微位移。
- **觸覺回饋**：按住測量時持續震動，量表「差點到頂又掉下來」時有額外震動。
- 語氣：儀器很認真（ERR 07、CFM 01、ε = 0.80），內容很廢（「對方大概在洗澡」）。

## 6. 畫面（共 9 頁）

| # | 畫面 | 功能 |
|---|---|---|
| 00 | 開機動畫 BOOT | 2 秒開機畫面（點一下可跳過）；有未完成的交換時回到收據，否則進首頁 |
| 01 | 待機觀景窗 HOME | 「我先開始測」／「我有對方的序號」；右上可進設定、紀錄 |
| 02 | 輸入對方序號 SERIAL | `SM-` + 6 位數字鍵盤；RND 填入一組有效的隨機序號（彩蛋）、DEL 刪除；A 回來輸入時標題為「輸入對方回傳的序號」；返回鍵：A 已測過→回收據，否則→首頁 |
| 03 | 校正問題 CALIB | 從 10 題題庫抽 3 題（A 隨機抽，B 沿用 A 序號裡的題組）、每題 4 選 1，每個選項附一個假溫度；選完 0.26 秒自動下一題 |
| 04 | 按住測量 HOLD | 按住 5 秒；量表會「快到頂→掉回→再衝」三次，最後才鎖定；中途放開歸零；狀態文字輪播。完成時產生自己的序號 |
| 05 | 快照收據 RECEIPT | 白色收據：我的序號、HOLD TIME、PEAK TEMP、答案、有效 24H。按鈕見 §7.3 |
| 06 | 配對報告 REPORT | 配對度（數字往上跑）、稱號＋描述、3 條細項指標、兩組序號；「匯出熱像報告」（產生報告圖片 → 系統分享選單，可存相簿或傳給對方）、「再測一次」（需確認） |
| 07 | 設定 SETUP | 溫度單位、發射率 ε、掃描線開關、回復原廠設定 ——「完全不影響結果」 |
| 08 | 歷史紀錄 LOG | 傳出或複製過的序號，狀態「等待回傳／已配對」；底部「清空紀錄」；空狀態文案 |

開發模式（DEBUG）右下有 INDEX 按鈕可直接跳任一頁（直接跳報告時沒有對方序號，結果不準）。

## 7. 核心流程

### 7.1 流程（已實作）

```
A：首頁「我先開始測」→ 3 題 → 按住 5 秒 → 收據（序號 SA）→ 傳送給 B
   → 「對方回傳了 · 輸入他的序號」→ 輸入 SB → 報告
B：首頁「我有對方的序號」→ 輸入 SA → 3 題 → 按住 5 秒 → 收據（序號 SB）
   → 傳回給 A → 「看配對報告」→ 報告
```

A 和 B 的報告完全相同。

### 7.2 序號與結果規則

- **格式**：`SM-` + 6 位數字 = 5 位資料 + 1 位檢查碼（`SerialCodec.swift`）。
- **資料**：`隨機碼 × 7680 + 題組編號 × 64 + 答案碼`（最大 99,839）。題組編號 = 10 題選 3 的 120 種組合之一（0–119）；答案碼 = 3 題答案（各 0–3）組成的 0–63；隨機碼 0–12。對方可從序號讀回你的題組與答案，不需要伺服器。
- **避免撞號**：B 產生序號時會避開 A 的隨機碼，即使答案完全相同也不會和 A 同號。
- **檢查碼**：權重 1/3/7/9/1，任何單一位數打錯都能擋下。
- **結果只由兩組序號決定**：兩組序號排序後合併，用固定 hash 計算（不能用 Swift 的 `hashValue`，每次啟動會變）。
- **配對度**：依相同答案數分段，段內由 hash 決定落點（= 下限 + hash % 段寬）。0 題 30–59、1 題 45–74、2 題 60–89、3 題 85–100。相鄰段落重疊，稱號不會被題數完全決定，但 3 題全同一定 ≥ 85。
- **細項指標**：每題對應一條指標（例如動物相容、電量焦慮差、作息時差），依抽到的 3 題產生；答案相同時數值落在「看起來很合」的區間（「XX差」類指標為低值，其他為高值）。

### 7.3 收據畫面按鈕

| 狀態 | 按鈕 |
|---|---|
| 還沒傳出 | 主按鈕「傳送給對方」→ 系統分享選單；小按鈕「只複製序號 COPY」；點序號本身也可複製 |
| 已傳出或已複製 | 「傳送給對方」變成外框按鈕「再傳一次」；主按鈕換成下一步：A「對方回傳了 · 輸入他的序號 →」／B「看配對報告 →」；A 另顯示「WAITING FOR PEER · 對方大概在洗澡」 |

- 分享選單按取消 **不算** 傳出；按複製算傳出。
- 分享文字：
  - A：「我在「靈魂配對測量儀」測好了，序號 SM-xxxxxx。換你測，測完把你的序號傳回來給我。」
  - B：「我也測好了，我的序號是 SM-xxxxxx。在「靈魂配對測量儀」輸入它，就能看我們的配對報告。」

### 7.4 錯誤與邊界狀況

| 狀況 | 行為 |
|---|---|
| 序號不足 6 碼 | `ERR 07 · 序號不足 6 碼` |
| 檢查碼錯誤（打錯） | `ERR 09 · 校驗失敗，這個靈魂不存在` |
| 輸入自己的序號 | `ERR 11 · 這是你自己的序號`（僅 A 在收據輸入自己的序號時提示；B 從首頁輸入不檢查） |
| A 輸入的回傳序號題組不同 | `ERR 13 · 題目對不上，這不是回給你的序號` |
| 測量中途放開 | 進度歸零，重新按住 |
| 再測一次 | 確認後作廢目前序號，回首頁，兩人要重新交換 |
| 關掉 App 再開 | 已測量完成、但還沒看過報告 → 開機後回到收據繼續（不論序號是否已傳出或複製）；其他情況進首頁。歷史紀錄會保留 |
| 開始新的一輪 | 舊序號作廢，不再自動回到收據；傳出或複製過的仍留在歷史紀錄 |
| 拒絕相機權限 | 熱像畫面退回靜態圖，流程照常 |

## 9. 技術備註

- 架構：單一 `@Observable MeterModel` 管全部狀態；`ContentView` 用 `switch` 切 9 個畫面。
- 保存：`MeterModel.Saved`（模式、兩組序號、是否傳出、是否看過報告、歷史紀錄）以 JSON 存進 `UserDefaults`，資料一有變動就自動存；題組與答案不另外存，從序號解回。存檔 key 為 `meter.saved.v2`（v1 格式序號不相容，舊資料不讀取）。設定頁的值目前不保存。
- 序號：`SerialCodec`（編碼、解碼、檢查碼、固定 hash）。
- 分享：`SharePresenter` 包 `UIActivityViewController`，才能知道使用者是否取消（`ShareLink` 做不到）；可分享文字或圖片。
- 匯出報告：`ReportExportCard` 以 `ImageRenderer` 輸出 390×844pt @3x（1170×2532）靜態圖，無按鈕、無動畫，底部加 App 名稱。已設定相簿寫入權限說明（「儲存影像」需要）。
- 相機：`ThermalCamera`（AVFoundation + Vision + CoreImage），已設定相機權限說明。
- 專案預設 MainActor 隔離、Swift 5 語言模式。
- 隱私：無網路請求、無追蹤、不收集資料。`PrivacyInfo.xcprivacy` 申報 UserDefaults（CA92.1）與系統開機時間（35F9.1，`CACurrentMediaTime`）。權限說明：相機、相簿寫入。
- iPhone 鎖直向（介面是直向設計）；iPad 保留全方向以支援多工分割畫面。
- 圖示與名稱：單一 1024×1024 `AppIcon`（`Assets.xcassets`）；主畫面顯示名稱以 `INFOPLIST_KEY_CFBundleDisplayName` 設為「靈魂配對測量儀」。
